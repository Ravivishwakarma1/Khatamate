01 · Architecture

System Architecture

A full-stack web application with offline-first capabilities, cloud sync, and real-time multi-device support.

┌─────────────────────────────────────────────────────┐ │ CLIENT (Browser) │ │ Next.js 14 App Router · TypeScript · PWA │ │ ───────────────────────────────────────────────── │ │ Zustand (state) · IndexedDB (offline cache) │ │ Fuse.js (fuzzy search) · Recharts (charts) │ │ next-intl (i18n) · React Hook Form + Zod │ └────────────────────┬────────────────────────────────┘ │ HTTPS / REST / Realtime WebSocket ┌────────────────────▼────────────────────────────────┐ │ BACKEND (Supabase) │ │ ───────────────────────────────────────────────── │ │ Auth: Email+Password · Google OAuth · Email OTP │ │ Database: PostgreSQL (Row-Level Security) │ │ Storage: Supabase Storage (photos, PDFs, backups) │ │ Realtime: Live sync across devices │ │ Edge Functions: PDF generation, bulk operations │ └─────────────────────────────────────────────────────┘ │ CDN + Edge Network ┌────────────────────▼────────────────────────────────┐ │ DEPLOYMENT (Vercel) │ │ Auto-deploy on git push · Preview per PR │ │ Edge functions · Global CDN │ └─────────────────────────────────────────────────────┘

Key Design Decisions

🔌

Offline-First

All reads/writes go to IndexedDB first. Supabase syncs in the background. Zero downtime regardless of connectivity.

🔐

Row-Level Security

Every database row is protected by Supabase RLS policies. Users can only access data belonging to their shop.

📱

PWA + Responsive

Installable as a home screen app on mobile. Desktop sidebar + mobile bottom nav with identical functionality.

💬 WhatsApp Integration (No API Required)

When the shopkeeper clicks "Send Reminder", a modal opens with a pre-filled message template. The user can edit the message, then clicking "Send via WhatsApp" opens: https://wa.me/91{phone}?text={encodedMessage} — which redirects directly to WhatsApp with the message ready to send. No WhatsApp Business API, no approval, no cost.

💾
2.1 — Data Layer

Offline Cache + Sync Engine + Business Logic

📥 IndexedDB Offline Cache (lib/db/idb.ts)
  • Local mirror of customers and transactions tables
  • All UI reads from IndexedDB first — instant render, no loading spinner
  • Write-through: writes go to IndexedDB immediately, then queued for Supabase
  • Pending queue stores failed syncs for retry
🔄 Sync Engine (lib/db/sync.ts)
  • Runs on app load and on window online event
  • Fetches delta: records newer than last_synced_at from Supabase
  • Flushes pending local writes to Supabase
  • Conflict resolution: Last-Write-Wins with server timestamp
  • Shows sync status indicator in settings
💰 Advance Wallet Logic (lib/finance.ts)

addCredit(₹500) — Customer has ₹200 advance

advance_balance: ₹200 → ₹0
outstanding_due: ₹0   → ₹300
(₹200 deducted from wallet,
 ₹300 added as outstanding)

recordPayment(₹700) — Outstanding ₹500

outstanding_due:  ₹500 → ₹0
advance_balance: ₹0   → ₹200
(₹500 clears dues,
 ₹200 goes to advance wallet)

10 · Phase 5

⚫ Phase 5 — Power Features & Polish

Week 6. Goal: QR cards, dispute workflow, write-offs, family accounts, one-tap repeat, remaining 6 languages, and final UI polish.

📱

QR Customer Cards

Generate QR code per customer (encodes their profile URL). Printable card with shop name + QR. Scan from any device to open profile instantly.

✍️

Write-Off (Bad Debt)

Write off uncollectible amounts with a mandatory reason. Permanently logged as WRITEOFF in timeline. Reduces outstanding balance.

⚠️

Dispute Workflow

Flag any transaction as disputed. Requires a note. Shows ⚠️ badge in timeline. Owner can resolve and close disputes.

👨‍👩‍👧

Family Accounts

Link customers under one household. Family view shows combined outstanding with per-member breakdown. Useful for hostel/colony shops.

🔁

One-Tap Repeat

"Repeat Last" button in Add Credit modal. Instantly fills previous transaction's amount and items. Perfect for daily milk/recurring orders.

🌐

11 · Deployment

Deployment Plan

Zero-server-management stack. Supabase handles backend, Vercel handles frontend — both scale automatically.

🗄️ Supabase (Backend)

  • Create Supabase project (start on free tier)
  • Run migration SQL files in order
  • Enable Email Auth + Google OAuth provider
  • Configure email templates (verification, reset)
  • Set up Storage buckets (customer-photos, pdf-exports)
  • Enable Row Level Security on all tables
  • Copy SUPABASE_URL and ANON_KEY

🚀 Vercel (Frontend)

  • Connect GitHub repository to Vercel
  • Set environment variables: SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, APP_URL
  • Every git push to main → auto-deploys
  • Every pull request → preview deployment
  • Enable Vercel Analytics for performance monitoring
  • Configure custom domain (optional)
